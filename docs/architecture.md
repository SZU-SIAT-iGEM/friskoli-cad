# 架构约定 · 阶段 1

本页保留已交付架构的基本边界。2026-09-29 的完整 CAD 目标架构与源码迁移方案见[架构与文件结构](design/architecture-and-packages.md)，产品与计划总入口见[工程设计总纲](design/README.md)。新目录为渐进目标，并非已存在的实现。

本文规定交付仓库的边界。已确定的数据字段与连接规则见[协议 0.1.0](protocol-0.1.md)；首个计算接口及数值例子见[无扩散摄取循环](engine-runtime.md)。

2026-10-02 补充：所有机制均按“系统 → 基础模块 → 特殊模块”划分职责。系统规定指标、单位、状态归属、资源与几何约束及提交规则；基础模块提供简单可复用行为；特殊模块提供有来源的模型方程或组合，并接受相同系统规则。两类模块都必须正式注册，案例只保存对象、参数与连接。该关系不要求每个特殊模块继承一个基础模块类，也不要求同一行为的多个实现同时运行。当前代码位置、各执行 profile 的可用范围与尚未统一的部分见[模块指南](module-guide.md#所有机制的三层关系)。

## 数据流

项目快照包含场地、空间对象、行为图、参数来源和运行设置。图编译器根据模块登记表检查连接、单位、状态与执行顺序。计算核心推进菌体和环境状态，记录器输出指标、帧及单菌体事件。服务传输结果；前端按时间与菌体 ID 展示。项目编辑状态由前端持有，运行使用提交时的不可变快照。

## 模块与行为图

- 共享协议描述模块标识和版本、作用范围、输入输出端口、参数、内部状态及时间语义。端口要说明数据形状和物理单位。
- 行为图保存模块实例及其连接。默认模板可以提供常用结构；计算核心依据通过校验的图运行，不把固定插槽写成扩展上限。
- 环境输运、边界、源释放等模块与感知、运动、摄取、表面展示等菌体模块同样可登记和替换。图编译器需要检查它们之间的耦合。
- 化学物质按物种标识管理，可有各自的浓度场和初始条件；摄取、释放、输运与外界交换由模块定义。氧将按这一规则接入，不能只凭物种名称推定耗氧或气液交换已经实现。
- 空间计算显式选择薄层或完整 3D；薄层厚度属于物理场地参数。菌体尺寸与环境格距需要分别建模，格距是否足够由所用机制与收敛检查决定。见[空间尺度说明](spatial-resolution.md)。
- 菌体几何、物种浓度、环境黏度与输运参数各有不同的状态归属和更新者；后续扩展与版本规则见[状态归属说明](state-ownership.md)。
- 共享功能使用通用名称。例如“表面展示”描述功能，INP 属于具体锚定实现或预设。科学含义和参数来源随具体实现保存。
- 同一步连接与读取上一步状态的连接必须有明确语义；循环、单位不符和缺少必需输入在运行前报告。

## 单菌体结果

菌体组定义共用的行为图及初始条件；每个菌体在一次运行中有稳定身份。结果协议需要表达运行 ID、帧顺序、模拟时间、菌体 ID、所属组、位置、朝向、可观察状态，以及出生、分裂、死亡等事件。分裂还要能关联亲代与子代。

前端根据这些记录建立和更新可见菌体，允许选择一个菌体查看其历史。画面中的大量菌体采用批量渲染；后端负责科学状态的演化，前端负责展示、插值和交互。记录频率与显示抽样不改变全体菌体的计算和群体指标。

## 仓库职责

2026-10-01 当前代码位于 `src/friskoli_cad/`：`protocol/` 保存合同与校验，`engine/` 保存编译和数值状态，`science/` 保存选定科学方程及证据，`tasks/` 管理持久异步任务，`web/` 与 `examples/` 是随包资源。HTTP 入口仍为 `replay_service.py`，M4 命令行入口为 `checkpoint.py`，没有为目标架构额外建立空的 `server/` 目录。仓库根部 `tests/` 与 `examples/` 保存验证和开发示例。原型、实验数据和旧引擎留在各自目录；迁入通过 `CONTRIBUTING.md` 的检查。
