# 当前项目与后续开发顺序

更新：2026-10-01。本页是当前开发顺序入口；逐阶段历史和测试记录见 [PROGRESS.md](../PROGRESS.md)。N1、N2、N3 M0–M4 及空间无偏基线已实现，下一项是 M5 信号—运动与对照。两份 WIKI 设想与用户历程已纳入[工程设计总纲](design/README.md)。阶段依赖和验收见[开发路线](design/roadmap-and-acceptance.md)，[协议扩展计划](protocol-expansion-plan.md)保留原能力清单。

## 现在有什么

Friskoli-CAD 可从源码或已验证的 Python wheel 启动，包含版本化协议、可编辑工作区、异步计算与结果回放。不同执行规则各自协商能力，不能把一套规则已有的机制自动计入另一套。

| 当前执行规则 | 已实现内容 | 明确边界 |
| --- | --- | --- |
| `legacy-explicit-v1` | 有限场/理想恒浓度储库、全域输入日程、定时转向、演示性增长与长度 adder 分裂、ID 和事件回放 | 这些演示机制未按真实菌株标定；不使用新空间胶囊碰撞与 checkpoint |
| `conservative-pts-bulk-v1` | 8 类模块、两种来源的 PTS 容量、有限均匀养分、共享摄取结算、胞内累计、EI/CheA/CheY | 固定菌体，motor bias 仅为读数；详见[最小 PTS 链](science/pts-minimal.md) |
| `spatial-unbiased-v1` | 14 类模块、注册障碍/实体底物/引诱物源、有限接触酶降解、局部扩散与共享摄取、胶囊碰撞、无偏 run/tumble | 当前无生长、分裂或外部日程；PTS 信号尚未改变运动；详见[空间基线](science/spatial-baseline.md) |

N1 的注册目录驱动对象库、属性与图绑定；放置底物自动生成必需降解机制，删除最后一个兼容机制受到依赖检查。Space/Workflow 支持编辑、检查、撤销/重做、名称与 ID、组合节点和缩放。N2 提供持久队列、幂等提交、取消、事件查询与原子结果分块。结果属于冻结的运行输入，修改草稿不会改变旧结果。空间 Task 0.3 还能输出真实浓度场和来源/材料库存；耗尽材料在回放中按对应帧隐藏。

M4 已补齐当前空间 profile 的独立随机流、完整状态、失败回滚及保存恢复。新的[自包含 checkpoint 文件与 CLI](checkpoint-files.md)可以从已提交步在另一个 Python 进程继续计算；恢复检查库存账、几何、ID、时钟、RNG、帧检查器和实现版本。连续 50 步与 20+保存恢复+30 步一致，改变输出帧间隔不改变相同数值步的结果。详见 [M4 验收](verification-m4.md)。这项能力不恢复服务器中 interrupted 的任务；任务级暂停续算仍在 N7。

当前仍缺完整趋化反馈、MCP 受体感知/适应、营养耦合生长、真实死亡、完整纤维化学、膜材料账、设计候选比较和标准导出。碰撞是保守的几何阻挡，不包含真实接触力或贴壁机制；实体部分降解仍保留原盒体边界。数值与随机复现不代表实验标定，旧性能数字也不代表当前完整空间场景。

N1–N5 是首个 CAD 产品流程的主线。界面一致性按[专业工具界面规范](design/professional-ui-reference.md)完成启动窗口首轮统一；图组件、名称与 ID、缩放和白色控件的首批改进随 N3 M0–M3 实施，实际范围和未测事项见该规范第 8 节。原 4c–5 的每项能力均保留，映射和详细错误路径见[新版路线](design/roadmap-and-acceptance.md)。协议重设计不能等待所有设想一次完美；每个新合同用最小正反例和迁移验证推进。

## 下一项：M5

1. 核对并登记信号到 motor 的方程、参数出处和计算时序；保持未标定参数的探索性标记。
2. 分别实现瞬时 tumble 与有限驻留时间规则，明确事件率改变时剩余 hazard 的推进，沿用 M4 完整保存和回滚。
3. 建立三类对照：PTS 的底物产物、引诱物与摄入养分共享有限场；MCP 使用均匀恒定、视为无限供应的营养背景及独立引诱物梯度；关闭趋化信号保留无偏运动。它们是明确的案例设置，不把 MCP 的环境条件推广为所有受体机制的定义。
4. 比较方向漂移、迁移/富集与驻留等有明确定义的指标，完成多 seed 重复和 dt/grid 敏感性，区分趋化与单纯速度变化。

通过这部分科学验收后再进入 N4 的目标、候选和设计比较。当前不把轨迹动画当作趋化有效性的证据。

## 保留的工程边界

前端以英文作为默认界面语言，在 Settings 中切换；布局按专业软件工作区组织。旧版 WebUI 用来对照信息结构和操作经验，当前代码不直接复制它。手机竖屏、横屏、平板和桌面分别检查可读性、触控尺寸及面板滚动；浏览器尺寸模拟与实体设备实测分开记录。

当前扩散使用显式给定的系数，没有从黏度推算。介质黏度若要参与计算，按[状态归属说明](state-ownership.md)成为环境参数或场，并由明确的模块决定它如何影响各物种输运或菌体运动。温度目前不在计划中。

物种目录目前保存 ID、浓度单位、初始值和来源，尚没有可导入任意物性参数的通用格式。后续导入现实物质时，属性还需写清物理量、单位、适用介质或条件和来源；只有明确读取该属性的模块才会改变运行结果。登记本身不会触发扩散、反应或耗氧。这项扩展安排在具体科学机制接入之前设计和验证。

运行中更换环境模块、迁移内部状态和运行中重划网格均需明确映射及事件，安排在 N7，不再作为第一科学案例的前置。创建新运行时选择环境、独立浓度场重划的已交付能力继续保留。推荐格距仍需具体机制的空间与时间步检查。

旧项目保持[原移动时间顺序](moving-cells.md)。N3 对具体 MCP/PTS 机制声明浓度、接受摄取通量及响应时段；新的连续/同段耦合按独立 execution profile 验证。空间无偏 profile 已有胶囊与器壁/实体的碰撞保护，旧中心点反射与长度 adder 不因此获得该能力。真实贴壁、独立出生/死亡、不对称分裂、营养与材料耦合仍需各自机制和完整状态规则。
