# 当前项目与后续开发顺序

更新：2026-09-28。本页记录开发安排；实际完成情况和验证数量以 [PROGRESS.md](../PROGRESS.md) 为准。每完成一步，先检查结果和限制，再更新这两处及相关说明。

## 现在有什么

Friskoli-CAD 目前是一个**可从源码运行的后端数值核心与版本化协议**，尚无运行服务和新前端。行为图连接带形状、物理量、单位、物种与时间语义的模块；编译器检查连接并确定执行顺序。单菌体有稳定 ID、位置、朝向和可选的初始胶囊尺寸，每步可输出逐菌体数值帧。尺寸尚未进入逐帧结果。出生、分裂、死亡有协议与序列检查，数值运行器尚未实际创建或删除菌体。

环境可选有限库存或理想恒浓度储库；空间可选单层薄层或完整 3D。[项目快照](project-schedule.md)现可保存物种目录和全域外部输入日程，物种也可只登记而不参与运行；显式启用两种物质时，浓度与外部物质账互不串用。[项目 `0.2.0`](capsule-geometry.md)可声明初始胶囊尺寸，并检查已知尺寸能否放进薄层。摄取可选最近格点或固定物理作用范围的采样和沉积；已有[基础扩散](no-flux-diffusion.md)和[演示性移动菌体](moving-cells.md)。独立工具能按体积守恒地重划浓度场，但不能迁移一场运行的全部状态。已有格距与时间步诊断，没有经生物场景验证的默认格距。

现在还没有趋化反馈、障碍物、生长、运行中可变尺寸、耗氧机制、局部环境入口或黏度场。扩散目前只覆盖均匀系数与无通量边界；运动目前是定时转向、匀速直行和中心点边界反射；输入日程目前只处理按步边界变化的全域速率。旧版 WebUI 和模型项目只作为迁入参考；它们没有混入这个交付仓库。先前的速度数字只对应当时无扩散、固定菌体的基准场景，不能代表后续完整模型。

## 按这个顺序继续

[基础扩散](no-flux-diffusion.md)、[演示性移动菌体](moving-cells.md)、[物种目录及输入日程](project-schedule.md)和[初始胶囊尺寸](capsule-geometry.md)已完成。接下来的顺序是：

| 顺序 | 下一步 | 完成时要看见什么 |
| --- | --- | --- |
| 1 | **生长与分裂。** 初始尺寸及来源已可声明；接下来定义逐帧几何协议，让生长模块更新单菌体尺寸，再接数值运行中的分裂与其他生命周期事件 | 旧项目继续读取；尺寸未知时不假装通过几何检查；分裂后的两个菌体各有 ID、几何与状态分配规则 |
| 2 | **运行服务与前端。** 传输项目快照、环境场和逐菌体帧；前端按 ID 展示与回放，并提供场地、格距和模块设置 | 行为图与数值运行结果能由用户检查；手机竖屏、横屏、平板、桌面分别验证，浏览器模拟与实体设备结果分开记录 |
| 3 | **科学模型迁入与交付。** 每个机制逐项迁入、标注证据和适用范围，再做性能、设计比较、导出与发布 | 新旧结果差异可追溯；真实参数和数值限制有记录；性能基准包含实际启用的模块 |

当前扩散使用显式给定的系数，没有从黏度推算。介质黏度若要参与计算，按[状态归属说明](state-ownership.md)成为环境参数或场，并由明确的模块决定它如何影响各物种输运或菌体运动。温度目前不在计划中。

物种目录目前保存 ID、浓度单位、初始值和来源，尚没有可导入任意物性参数的通用格式。后续导入现实物质时，属性还需写清物理量、单位、适用介质或条件和来源；只有明确读取该属性的模块才会改变运行结果。登记本身不会触发扩散、反应或耗氧。这项扩展安排在具体科学机制接入之前设计和验证。

运行中更换环境模块、迁移其内部状态，以及运行中重划整场网格，都需要状态映射和可回放规则。这些任务排在项目快照与运行状态格式稳定之后；目前创建新运行时可以选择环境模块，独立浓度场可以守恒重划。前端允许用户选择格距，但给出科学上的推荐值还要等具体机制的空间与时间步检查。

趋化反馈的后续工作按[移动时间顺序](moving-cells.md)接入：MCP 使用新位置的浓度与当前摄取通量计算下一段的转向指令；PTS 模块读取已声明的逐菌体摄取通量。需要连续、同段耦合时，先选择并验证子步或耦合方法。障碍物和真实贴壁行为要在菌体尺寸、障碍物几何及碰撞规则明确后加入，当前矩形边界反射不代表它们已经实现。
