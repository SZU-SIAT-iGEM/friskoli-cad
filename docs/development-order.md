# 当前项目与后续开发顺序

更新：2026-09-28。本页记录开发安排；实际完成情况和验证数量以 [PROGRESS.md](../PROGRESS.md) 为准。每完成一步，先检查结果和限制，再更新这两处及相关说明。

## 现在有什么

Friskoli-CAD 目前是一个**可从源码运行的后端数值核心与版本化协议**，尚无运行服务和新前端。行为图连接带形状、物理量、单位、物种与时间语义的模块；编译器检查连接并确定执行顺序。单菌体有稳定 ID、位置和朝向，每步可输出逐菌体数值帧。出生、分裂、死亡有协议与序列检查，数值运行器尚未实际创建或删除菌体。

环境可选有限库存或理想恒浓度储库；空间可选单层薄层或完整 3D。浓度按物种标识，已经验证一场运行里两种物质互不串用。摄取可选最近格点或固定物理作用范围的采样和沉积；已有[基础扩散](no-flux-diffusion.md)和[演示性移动菌体](moving-cells.md)。独立工具能按体积守恒地重划浓度场，但不能迁移一场运行的全部状态。已有格距与时间步诊断，没有经生物场景验证的默认格距。

现在还没有趋化反馈、障碍物、生长、可变尺寸、耗氧机制、环境变化日程或黏度场。扩散目前只覆盖均匀系数与无通量边界；运动目前是定时转向、匀速直行和中心点边界反射。旧版 WebUI 和模型项目只作为迁入参考；它们没有混入这个交付仓库。先前的速度数字只对应当时无扩散、固定菌体的基准场景，不能代表后续完整模型。

## 按这个顺序继续

[基础扩散](no-flux-diffusion.md)与[演示性移动菌体](moving-cells.md)已完成。接下来的顺序是：

| 顺序 | 下一步 | 完成时要看见什么 |
| --- | --- | --- |
| 1 | **项目级物种目录与环境输入日程。** 把物种、初始条件、输入单位和作用范围写入项目快照，按时间边界应用外部输入 | 每个物种的场和外部物质账独立；日程可保存、回放并重现；氧可作为物种登记，但耗氧与气液交换仍由具体模块提供 |
| 2 | **菌体尺寸、生长与分裂。** 先声明初始尺寸及来源，再让生长模块更新单菌体几何，最后接数值运行中的分裂与其他生命周期事件 | 旧项目的读取规则和新版协议明确；尺寸未知时不假装通过几何检查；尺寸已知时检查薄层容纳条件；分裂后的两个菌体各有 ID、几何与状态分配规则 |
| 3 | **运行服务与前端。** 传输项目快照、环境场和逐菌体帧；前端按 ID 展示与回放，并提供场地、格距和模块设置 | 行为图与数值运行结果能由用户检查；手机竖屏、横屏、平板、桌面分别验证，浏览器模拟与实体设备结果分开记录 |
| 4 | **科学模型迁入与交付。** 每个机制逐项迁入、标注证据和适用范围，再做性能、设计比较、导出与发布 | 新旧结果差异可追溯；真实参数和数值限制有记录；性能基准包含实际启用的模块 |

当前扩散使用显式给定的系数，没有从黏度推算。介质黏度若要参与计算，按[状态归属说明](state-ownership.md)成为环境参数或场，并由明确的模块决定它如何影响各物种输运或菌体运动。温度目前不在计划中。

运行中更换环境模块、迁移其内部状态，以及运行中重划整场网格，都需要状态映射和可回放规则。这些任务排在项目快照与运行状态格式稳定之后；目前创建新运行时可以选择环境模块，独立浓度场可以守恒重划。前端允许用户选择格距，但给出科学上的推荐值还要等具体机制的空间与时间步检查。

趋化反馈的后续工作按[移动时间顺序](moving-cells.md)接入：MCP 使用新位置的浓度与当前摄取通量计算下一段的转向指令；PTS 模块读取已声明的逐菌体摄取通量。需要连续、同段耦合时，先选择并验证子步或耦合方法。障碍物和真实贴壁行为要在菌体尺寸、障碍物几何及碰撞规则明确后加入，当前矩形边界反射不代表它们已经实现。
