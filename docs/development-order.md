Friskoli-CAD 可从源码或已验证的 Python wheel 启动，包含版本化协议、可编辑工作区、异步计算与结果回放。不同执行规则各自协商能力，不能把一套规则已有的机制自动计入另一套。

| --- | --- | --- |
| `legacy-explicit-v1` | 有限场/理想恒浓度储库、全域输入日程、定时转向、演示性增长与长度 adder 分裂、ID 和事件回放 | 这些演示机制未按真实菌株标定；不使用新空间胶囊碰撞与 checkpoint |
| `conservative-pts-bulk-v1` | 8 类模块、两种来源的 PTS 容量、有限均匀养分、共享摄取结算、胞内累计、EI/CheA/CheY | 固定菌体，motor bias 仅为读数；详见[最小 PTS 链](science/pts-minimal.md) |

## 保留的工程边界

前端以英文作为默认界面语言，在 Settings 中切换；布局按专业软件工作区组织。旧版 WebUI 用来对照信息结构和操作经验，当前代码不直接复制它。手机竖屏、横屏、平板和桌面分别检查可读性、触控尺寸及面板滚动；浏览器尺寸模拟与实体设备实测分开记录。

旧 profile 继续使用显式给定的扩散系数；新 profile 可通过独立注册的黏度模块按声明关系推算。介质黏度若要参与计算，按[状态归属说明](state-ownership.md)成为环境参数或场，并由明确的模块决定它如何影响各物种输运或菌体运动。温度场求解不在当前范围，关系式使用显式给定的条件温度。

物种目录继续保存 ID、浓度单位、初始值和来源；新 profile 的条件物性目录模块接收可导入的结构记录，声明单位、适用条件、来源、不确定性与未知值。后续导入现实物质时，属性还需写清物理量、单位、适用介质或条件和来源；只有明确读取该属性的模块才会改变运行结果。登记本身不会触发扩散、反应或耗氧。具体支持及边界见[模块索引](module-reference.md)。

Task 0.6 可以从已提交 checkpoint 显式迁移同一物理域的网格与允许的环境参数，并记录映射及新运行段；Project 0.6 还可选择固定物理坐标的扩域零填充与零库存区域缩域。任意模块替换、未知状态映射、非零裁切外流和坐标缩放旋转保持拒绝。创建新运行时选择环境、独立浓度场重划的已交付能力继续保留。推荐格距仍需具体机制的空间与时间步检查。

旧项目保持[原移动时间顺序](moving-cells.md)。N3 对具体 MCP/PTS 机制声明浓度、接受摄取通量及响应时段；新的连续/同段耦合按独立 execution profile 验证。空间无偏 profile 已有胶囊与器壁/实体的碰撞保护，旧中心点反射与长度 adder 不因此获得该能力。新科学 profile 已有营养耦合、随机死亡和有界不对称分裂；新 profile 已有显式现象学黏附/接触模块；真实流体接触力和完整能量预算仍需进一步研究，膜材料库存已按用户决定取消。

## 系统与模块的边界

所有机制统一采用“系统 → 基础模块 → 特殊模块”的职责关系，不限于生长。系统管理数值调度、存储、资源预检、状态提交和表示误差；基础模块提供简单行为；特殊模块提供具体模型方程。两类模块都须注册参数、单位与来源，并遵守其执行 profile 的系统规则。案例只保存普通对象、参数和模块连接。实际模块与当前profile边界见[模块指南](module-guide.md)，数值实现见[系统级数值执行](numerical-resource-execution.md)。
