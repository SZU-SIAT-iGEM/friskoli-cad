初稿：2026-09-29；当前状态更新：2026-10-02。**N0–N3 已实现，N4 核心及多项修订已接入，当前进行 N5 完整模拟与主前端流程验收。**底盘/元件 assembly、分批比较、原生包、OMEX/显式 SBOL 子集和共享静态 viewer 已有实现；完整 10000 步尚未验收。实际功能、验证与限制见 [PROGRESS](../../PROGRESS.md)，顺序见[开发安排](../development-order.md)，逐项未完成计划见[剩余工作清单](../remaining-work.md)。

## 产品目标

帮助用户为一个明确的趋化工程任务提出候选设计，检查输入和假设，进行可复现的空间模拟，比较对照，导出可继续研究的设计包。首个完整案例是团队的 Friskoli 模型；开放插件用于替换或扩展机制。

产品流程为：**定义目标与约束 → 选择底盘/元件/参数证据 → 形成候选设计 → 编辑空间和行为图 → 检查并运行 → 比较结果 → 导出设计与证据**。只有空间编辑和回放时，应准确称为模拟工作区；达到上述流程的发布门槛后，才宣称具备完整 CAD 设计能力。

## 本轮工程决策

1. **增量重构，不全栈重写。** 保留当前 Python/NumPy 内核、图编译器、稳定 ID、守恒重划、结果回放及测试；重构前端状态分工、注册目录、应用服务和合同边界。暂不更换前端框架或桌面容器。
2. **协议分层修订，不统一清零。** 项目、工作区、模块、计算语义、任务、结果和插件各自版本化；旧格式通过显式迁移或受限兼容适配器读取。新草案未通过迁移测试前，不修改生产 Schema 的版本号。
3. **先交付一个完整科学案例。** 先让真实趋化模型、无趋化对照、最小比较和原生设计包贯通；运行中更换环境、高级接触力学和 GPU 不作为它的前置条件。
4. **四类职责，共享合同。** 交互应用、平台与数值运行时、科学插件、协议与数据模型保持清晰边界。另显式设置设计/比较应用服务，把科学模块组织成用户任务。
5. **Wiki 使用只读演示构建。** 仅允许从预计算示例开始；进入后仍可观察、回放、比较和下载公开结果。完整本地版使用同一查看组件，加上本机后端与编辑、计算能力。
6. **后台登记能力决定可用功能。** 物种、空间对象、场、算子、参数集、科学模型包和可运行后端分开登记。未知类型可以保留原始资料并显示占位，不能无声进入求解。
7. **数学说明与实现绑定。** 模块提供公式/算法说明、符号映射、单位、离散方法、代码标识、测试及来源；自报“等价”只作为声明，不能当作证明。
