# 专业工具界面参考与实施规范

日期：2026-09-29。状态：研究与待实施建议。本文件没有实现运行代码，不代表新增能力已交付。

## 1. 结论与本轮范围

当前启动窗口把口号、大按钮和预设卡片放在视觉中心，进入工作区后却变成紧凑侧栏、工具栏与属性行。最先需要修改这种信息层级差异。建议采用**同一工具外壳中的紧凑启动窗口**：清楚列出新建、打开、恢复与可运行示例，品牌只占短标题行。菜单、对象树、属性、视口和结果区共用尺寸与状态规则。

Blender、Blockbench 的参考价值在于命令、对象、当前选择、属性与工作区域的分工。全局改成深灰、缩小全部文字或复刻启动插图，都不能单独完成这种转变。Friskoli 保留克制的绿/蓝识别与易读无衬线。

最小改造只涉及欢迎窗口的结构、文案、样式与焦点行为。完整菜单、运行配置弹窗和其他面板另行实施。N1 当前提供类型/注册目录、几何读取与采样的纵向样例，**仍非科学趋化成品**；生长分裂示例和构造验证值不标为校准模型。

## 5. 区域规则

### 菜单与全局命令

- 文件、编辑、视图、帮助承担全局命令；Space、Workflow、Results tabs仅切换工作区。完整菜单后续独立实施。
- 工具条只放高频及当前模式动作；文字、tooltip、快捷键来自同一命令定义，没有实现的快捷键不显示。
- 右键菜单与触屏“更多”访问相同命令；危险动作分组。disabled原因可读取，未知模块保留可读草稿但明确阻止Run。

### 面板边界

- 左栏回答“有哪些对象/模块”，右栏回答“当前选中的属性”；不重复全局导航。
- 面板使用单条边界；每区独立滚动，切换tab尽量保持阅读位置。splitter支持拖动与键盘。
- 折叠后有显式重开按钮；小屏同时只覆盖一个主要侧栏。不为本次修正引入复杂浮动停靠系统。

### 弹窗

- 启动选择器与编辑表单共用标题栏、边线、按钮。启动命令点击即按原逻辑执行，不增加无意义确认按钮。
- 编辑表单按label/value/unit对齐；取消、应用固定在底部；错误就近显示。
- 原生dialog具有可访问名称；Tab不进入背景；打开、关闭的焦点可预期，关闭返回触发控件。
- 欢迎X、Esc和真正的backdrop点击只关闭，不新建或加载。当前全局event.target===dialog可能把内部空白也算关闭；实施时以指针是否在dialog矩形外判定backdrop并测试。
- 保留模糊偏好：建议3px blur加遮罩，让外壳可辨识；blur不可用时遮罩仍有效。

### Viewport

- 中央主要显示对象；品牌插图、长帮助和宣传说明不常驻覆盖主体。视图、选择、测量是不同状态。
- 对象树/viewport/属性选择同步；群组块、单菌体、场切片明确区分；显示选择不改变科学数据。
- 坐标、几何、浓度带单位；场有色标与切片位置。unknown不画成0。
- 鼠标、触控板、键盘、触屏分别验证；单指导航/拖动、双指缩放、pointercancel及手势切换需实际测试。
- 编辑指引只在编辑页触发；Results首次阅读说明单独处理。

### Workflow图编辑

- 默认显示功能名、群组、状态与关键端口，完整ID/version为次级信息；数据读取节点默认折叠。
- 建议节点220px宽，按端口数决定高度；标题13px，端口12px/24px行高。完整ID可复制，不挤成9px。
- 连接说明quantity/unit/entity/time；same_step与previous_step用不同线型并附文字。
- 拖线不兼容时给具体原因；端口视觉可小，触屏命中区至少44px且相邻区域不重叠。
- 方程、符号映射、假设、证据在Inspector展开；公式不能替代单位、版本与实现来源。

### Properties / Evidence

- 先显示选择名称与类型，再显示可编辑值；无选择仅短提示。
- 按位置/几何、参数、输入输出、科学说明分组；label左齐，数字右齐，unit固定尾列。窄屏值换行，单位仍可见。
- unknown、不适用、未提供按实际合同显示；无自动填0或静默截断。非法输入保留并报错。
- 示例值标“构造示例/未校准”；决定可运行性的限制不藏进tooltip。来源可展开。
- 一次完整数字编辑形成一条undo；选择、视角、折叠不污染科学输入。

### Results与底部面板

- 显示Run、输入修订/版本、完成状态、物理时间；草稿变化后持续提示结果来自先前输入。
- Timeline与Play/Pause明确为回放，不能暗示暂停/续算能力。模拟时间、solver step、保存帧不混称。
- 图表数据来自后端或定义清楚的派生指标；单位、分母、缺失状态可读。轨迹画面不证明趋化有效。
- Runs/Checks/Log/Data位于可折叠底部；诊断可定位对象/节点/字段；不把每步都刷成普通日志。
- 维持已有原生JSON/CSV导出；SBOL/OMEX、恢复后台任务等须相应阶段验收后才可用。

## 7. 实施顺序与验收

1. 先改欢迎窗口：保留ID/事件，改列表结构、文案与焦点。welcome样式与通用dialog分开，避免影响导出、JSON编辑。
2. 再统一面板/输入/折叠标题：保留信息，不靠全局缩字号获得密度。
3. 最后独立完善真实菜单和运行配置；保持history、快捷键、未保存保护及capability检查。

| 验收 | 可判定条件 |
| --- | --- |
| 视觉连续 | 欢迎与工作区同字体、控件、边线、色彩角色；无大宣传标题/大预设卡 |
| 第一眼选择 | 三个项目动作与两项示例可辨，科学限制在窗口内可见 |
| 操作安全 | 关闭/Esc/取消文件不改项目；窗口内空白不误关；覆盖仍确认 |
| 键盘 | Tab顺序、focus、Enter当前项、Esc、返回焦点均验证 |
| 能力准确 | 示例只载入；N1说明准确；没有无实现的任务/标准导出动作 |
| 尺寸 | 1440×900、1024×768、390×844、844×390分别检查，无页面横向溢出，全部动作可滚动到达 |
| 放大/长文 | 200%缩放、中英文、长错误、软键盘出现后仍能操作 |
| 手势 | 鼠标、触控板、一指/双指切换、pointercancel分别记录；横屏关闭/确认不隐藏 |
| 证据 | 浏览器尺寸模拟、手势逻辑测试、实体设备实测分开记录；本研究未执行这些测试 |
