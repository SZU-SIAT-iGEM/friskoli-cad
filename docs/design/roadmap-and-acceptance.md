# 开发顺序与验收

日期：2026-09-29。N0 文档已提交，N1 功能已实现，具体验证范围见 [PROGRESS](../../PROGRESS.md)。N2–N8 待实施。阶段顺序取代原“4c → 4d → … → 5”的固定排队，但不删除原计划能力。历史完成记录保持原编号。

## 1. 发布目标

**首个 CAD 可交付版本**必须具备：一个真实科学模型包、目标与约束、至少两项候选和明确对照、检查、可恢复查询的计算任务、结果比较、完整原生设计包及 Wiki 只读演示。未完成的生物机制和标准适配不得写成发布能力。

完整 Friskoli × Cellulose 案例若需要表面接触、降解、营养耦合，必须完成对应 N6 子任务才能宣称复现；较早阶段只称最小趋化案例。通用 CFD、任意复杂网格力学、全自动序列设计、在线社区和分布式 GPU 不作为首个版本门槛。

## 2. 依赖与主线

```text
N0 文档设计
 └→ N1 类型/注册/旧格式适配 + 任务合同草案
      └→ N2 任务服务 + 草稿/视图/运行状态拆分
           └→ N3 首个趋化科学包与对照
                └→ N4 设计目标/候选/比较/原生导出
                     └→ N5 Wiki 演示、标准适配与发布验收
N1/N2 ─→ N6 空间/营养/材料深化 ─→ 完整 Cellulose 案例
N2 + 所需状态映射 ─→ N7 checkpoint 与环境迁移
N3–N7 实测瓶颈 ─→ N8 标定、性能与扩展
```

N6 的必要子任务可随 N3 迁入，不必等待整套高级接触力学；不能为了提前展示而删掉原模型必需机制。所有阶段均保留旧格式/旧结果对照，UI 变更随相关能力实施，不另等待最后一次全栈翻修。

## N0 工程规划（已提交）

- 已完成：用户材料与当前代码基线核对，产品与交互、目标目录、合同、数值规则、包/导出、迁移、路线和关键判断文档。
- 未包含：新 Schema、运行代码、插件实现、UI 重做、科学拟合或设备实测。
- 验证：16 份新建/更新文档的 135 个本地链接与锚点、2 段 JSON 示例解析通过，`git diff --check` 通过；核对原 4c–5 覆盖与新旧版本标记。改动仅为文档，不把历史测试数当作本轮重新测试。

## N1 类型合同与注册目录纵向样例

实施记录：[注册目录与工作区 0.3](../registry-contract.md)、[N2 任务合同草案](../protocol/task-contract.md)。Catalog 0.1 独立包装旧 manifest；Module/Graph/Project 的执行语义保持不变。新数据节点、声明属性、公式说明、旧文件报告与未知模块可读处理已加入。浏览器/安装包及未验证事项分别记录，视觉风格不因功能测试通过而视为用户已认可。

前置：N0。目标是在一个小用例中证明合同真正驱动前后端，避免先设计所有物理机制。

交付：

1. 将当前可用 manifest 和对象整理为 registry；Schema 草案覆盖端口单位/实体/时间、对象 initializer、公式说明、diagnostics、版本协商与任务状态。
2. 以现有菌群 + 胶囊读取/面积 + 浓度采样作为最小流程，补说明、符号映射、帮助和场/对象区别。几何读取只提供派生量，不顺便加入膜限制。
3. 前端通过声明生成库、属性与折叠的数据节点；场地/菌群/节点相互引用，自动生成关系可撤销并保存。
4. 旧项目/工作区/图 adapter 与 migration report，保留 legacy execution semantics。
5. 任务 OpenAPI/Schema、状态机、幂等/取消/失败样例定稿，为 N2 提供合同。

验收：新登记的受支持几何模块无需改硬编码列表即可出现；未知模块保持可读且阻止 Run；球极限面积/体积正确；同单位不同 quantity、跨组错连、缺值、越界、不同版本都可定位；放置—撤销—重做—保存—重开保持一致；现有示例与旧结果不变。

建议变更范围：protocol、registry、受控的 placeables/catalog/inspector、一个基础数学模块和 fixtures。不要先把 runtime.py、app.mjs 和整个目录同时拆完。

## N1 后的界面一致性（下一项）

用户新增的 Blender/Blockbench 参考已形成[专业工具界面规范](professional-ui-reference.md)。先把欢迎页改为紧凑启动窗口与示例列表，保留加载、恢复、未保存保护和背景模糊；再统一面板边界、属性行与控件尺寸。当前仅完成研究，尚未实施视觉改造。

验收分别覆盖实际操作、键盘焦点、窗口内部空白不误关闭、中英文和四种浏览器尺寸；明确区分浏览器尺寸模拟、手势逻辑检查与实体设备实测。这项调整不改变 N1 数值合同或提前宣称异步任务已完成。

## N2 异步任务与前端状态

前置：N1 的任务合同和 registry 冻结。

交付：单 worker、有界队列、SQLite 任务元数据、输入快照、分块结果、查询/取消/事件游标、服务重启后 interrupted 状态；前端 document/view/run stores 与 command 事务，旧同步接口保留小任务兼容。

验收：同键重试不重复计算、不同内容同键冲突、排队与运行取消、终态竞争、断线重连、worker 异常、磁盘写失败、资源超限均可恢复解释；运行中编辑不改变已提交输入；只公布完整已提交帧，partial 不冒充 completed；新结果不覆盖新草稿。

本阶段不自动承诺暂停续算。轮询足够时不先实现 WebSocket；输出量、总内存和任务数量有界。旧实现安装包中也能找到新增服务与 web 子目录资源。

## N3 首个真实趋化科学包

前置：N1、N2；模型所需基础能力必须先具备。

交付：审查现有科学模型代码/方程/参数，迁入感知与适应、摄取/PTS、MCP/运动所需的最小机制组合；建立可展开的模板、参数证据、适用域、真实图与无趋化对照。保留原模型固定条件作为回归。

验收：数据输入 → 采样/接受摄取 → 感知 → 运动 → 指标有清楚的时间语义；质量账和 RNG 可复现；固定输入与旧实现差异有解释；替换/关闭趋化分支得到有意义的对照；尚未校准的参数不标 calibrated。至少一个清楚定义的指标可以比较，不能仅凭轨迹动画认为有效。

如现有资料缺关键参数或实验数据，保留探索性状态与待测清单；不能编造参数以满足验收。

## N4 CAD 设计与比较

前置：N3。

交付：DesignBrief、底盘/元件/参数选择、有限规则候选枚举、硬/软约束、批量运行预算、独立重复、对照比较、原生设计包/CSV/HTML 报告。提供少量有证据的模板和高级编辑入口。

验收：用户从简短目标开始，形成候选，看到排除原因；至少两个候选与对照使用相同观测定义；重复与不确定性可查看；失败/未到达/分母为零不伪造数值；报告可回到相应输入、版本、运行与证据；重新打开包能复现实验设置。无可行候选时明确返回无结果，不能强推推荐。

## N5 Wiki、标准与发布

前置：N4；可提前抽取共享 viewer，但仅发布经过验证的记录。

交付：Wiki 静态模式、示例清单与完整 provenance、本地启动/安装验证、资源基准、用户教程、公开许可证；按支持条件实现 SBOL 子集、OMEX，并逐项补可复现 SBML/SED-ML 子模型适配。

验收：静态服务无 backend 仍可完整回放，不发求解请求；禁用启动/编辑入口有原因，阅读功能可用；原生包保持无损，各有损格式明确损失并可验证；没有序列时禁用 GenBank；跨机器从发布包启动而非只在源码目录成功。

UI 检查覆盖桌面、平板、手机横竖屏；区分浏览器尺寸模拟、手势逻辑与实体设备。验证键盘/触控板、双指切换、取消、抽屉滚动、软键盘、安全区、旋屏和阅读位置恢复。未测试设备不能标为已支持。

## N6 空间、营养与材料深化

前置：N1 类型/几何与 N2 事务状态；根据 N3/完整 Cellulose 案例选择必需子集。

交付：胶囊—边界/简单障碍/菌体的接触处理、初始化无重叠、受阻运动/生长/分裂、局部源/表面降解、黏附/脱附、营养与能量/死亡、可选膜材料和受体资源、通用条件化物性/黏度。

验收：严格模式无穿模；受阻与错误/死亡分开；营养与材料不重复结算；未启用可选机制不凭空施加限制；物种登记不产生逐步负担；两物质独立账、分裂几何/面积与状态继承正确；适用域与科学证据逐机制记录。接触力学精度超出首版时明确限制，不用任意反弹替代验证。

## N7 Checkpoint 与运行中环境迁移

前置：N2、目标模块的完整状态映射；涉及网格/几何变化时还需 N6 相应能力。

交付：checkpoint、可验证的暂停/续算；在已提交边界上预演环境/网格迁移、保存映射与事件，失败只取消替换。

验收：中断后续算与不中断的参考运行在声明容差内一致；RNG、ID、内部状态和未来日程完整；没有状态映射时拒绝；同域守恒重划与改变物理域范围分别处理；原运行和原结果可查。

## N8 标定、性能与更广扩展

前置：实际科学用例和可测量瓶颈。

交付：参数可辨识性与标定/留出验证、敏感性与适用区间图；按数据评估并行、GPU、稀疏场、大结果存储；高级几何/流动与更多插件按需求增加。社区分享、自动优化与序列设计保持独立范围。

验收：性能提升有基准、规模、硬件、统计和结果一致性；敏感性结论附范围与模型版本；模型预测与实验验证分开；不得以展示刷新速度代替内核吞吐量。

## 4. 横向验收矩阵

| 范围 | 必测成功路径 | 必测错误/边界 |
| --- | --- | --- |
| 类型/注册 | 新声明出现于库与表单 | 重复 ID、缺依赖、未知对象、后端不支持 |
| 对象/图联动 | 一次放置生成绑定、可撤销并重开 | 删除依赖、模板升级、手改保留、越界 |
| 草稿/运行/视图 | 运行后继续编辑、结果仍关联原输入 | 旧响应晚到、断线、恢复草稿失败 |
| 数值 | 守恒、稳定、薄层/3D、grid/dt 对照 | 负库存、NaN、超步长、事件跨步、回滚后 RNG |
| 生命周期 | 稳定 ID、分裂继承、death 原因 | ID 重用、跨组错位、无声明材料去向 |
| 任务 | 幂等提交、状态查询、原子完成 | cancel/complete 竞争、worker/磁盘失败、资源限额 |
| 比较 | 候选、对照、独立重复 | 没到达、零分母、partial、样本不足 |
| 文件/插件 | 保存、回读、依赖锁、损失报告 | 未来版本、路径越界、坏 checksum、未安装执行代码 |
| 发布/UI | 本地启动、静态离线查看、多端操作 | 无 backend、未知 renderer、软键盘、pointercancel |

每项记录 artifact、输入、版本、预期/实际、限制和复现方法。数值/科学/界面分别验收，不能用单元测试总数替代科学证据或实体设备测试。

## 5. 日常实施规则

- 从当前干净基线建立相应阶段分支，尊重既有未提交工作；不改写 main 历史。
- 每次变更围绕一条可验证的功能流程，同时提供正例、错误路径、旧例回归与说明。
- 能力实现后才加入 capabilities 的可执行列表，完成验收后才更新 PROGRESS。
- 协议、实现、示例、迁移和 UI 状态同时检查；无必要不搬目录或重选框架。
- 第一个实际变更仅开展 N1 的最小流程，其完成后继续 N2；本提案不要求一次实现所有理想结构。
