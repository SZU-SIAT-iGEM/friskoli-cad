# 协议扩展计划

更新：2026-09-29。

**计划已扩展：** 本页保留原 4c–5 的能力与验收清单。当前实施顺序采用[新版工程路线](design/roadmap-and-acceptance.md)，合同细节见[协议与执行设计](design/contracts-and-execution.md)，完整产品目标见[设计总纲](design/README.md)。原清单顺序不再代表硬性前置关系，环境热切换调整到首个 CAD 案例之后。

这份文档记录当前基线之后要引入的协议能力。它只描述边界、依赖和验收条件，暂时不改变现有 Schema 或运行器。

## 当前基线

| 层 | 当前版本 | 处理范围 |
| --- | --- | --- |
| 模块、行为图和连接规则 | `0.1.0` | 端口形状、物理量、单位、物种、参数、状态和时间语义 |
| 单菌体几何帧 | `0.2.0` | 胶囊尺寸、位置、朝向和事件序列 |
| 工作区 | `0.2.0` | 项目草稿、菌群体积块、图布局、运行设置 |
| Local API | `0.2.0` | capabilities、modules、validate、同步 replay |
| Replay | `0.1.0` | 不可变运行结果、帧、事件、环境场 |

现有共享模块协议继续保持兼容。工作区和 Local API 各自版本化，不能因为界面字段变化就一起升级所有协议。

## 扩展规则

1. 每个新增字段先说明所有权、物理量、单位、时间语义和来源。模块名称采用功能职责，具体模型名称只出现在实现或预设中。
2. 连接语义、内部状态、事件或结果帧含义变化时提升对应合同；只增加可选信息也先检查旧 Schema 是否接受。现有 `additionalProperties: false` 会拒绝未声明字段，因此 metadata 扩展不能无版本直接写入旧文件。
3. 工作区、模块图、运行传输和结果回放分别维护迁移表。前端不自行猜测后端能力，能否使用一个对象以 capabilities 和模块登记为准。
4. 运行中的状态改变必须能记录为事件，并能在失败时恢复到改变前的完整时间步。没有明确映射的状态不自动丢弃，也不静默复制。
5. 每一项扩展都要有最小可运行示例、错误示例、旧版本回归和资源边界测试；通过后再更新 `PROGRESS.md` 的完成状态。

## 保留的扩展清单（顺序见新版路线）

### 1. 运行任务与前后端传输

为长时间运行增加独立的任务生命周期。候选字段包括 `run_id`、`request_id`、状态、进度、错误路径、结果引用以及取消原因；同步 replay 保留给短任务和兼容调用。

验收时需要看到：

- 断线后可以根据 `run_id` 查询状态，不重复执行同一份提交快照；
- 取消只影响尚未完成的任务，已经发布的结果仍不可变；
- 失败、取消和资源超限都有稳定错误码与路径；
- 前端能显示排队、运行、完成、失败和取消，而不把局部帧当成完整结果。

### 2. 环境选择、运行中替换与状态迁移

创建运行时选择环境模块已经存在。下一步定义运行中替换的请求、适用时间点和状态映射：浓度场可以按重叠体积守恒重划，环境模块的内部库存、边界条件和累计量则必须由模块声明映射；没有映射时拒绝操作。

验收时需要看到：

- 同一菌体图可以接入第二种环境实现，并明确哪些状态被保留、转换或重新初始化；
- 替换事件进入回放，重复播放得到相同结果；
- 状态映射失败时整次替换回滚，原运行仍可继续查看；
- 网格重划、环境替换和输入日程不会互相冒充。

### 3. 通用物种、物性与状态归属

扩展项目级目录，使物质由稳定 `id` 区分，并可登记浓度、扩散率、黏度、密度或其他带单位的属性。登记只提供元数据，不会自动创建浓度场、扩散或耗氧计算；只有实际读取该属性的模块才产生运行开销。

黏度先作为环境参数；只有它随空间或时间变化时才升级为环境场。氧可以只登记，耗氧需要独立模块。表面展示、受体拷贝数和膜材料使用通用功能接口，不把某个蛋白名称写进接口。

验收时需要看到：

- 只登记但未接入图的物种不会生成数组或进入每步计算；
- 两种物质的场、摄取和物质账相互独立；
- 属性有单位、适用条件和来源，未知属性不会被模块默认为零；
- 模块声明自己读取和更新哪些状态，避免同一状态出现两个执行者。

### 4. 菌体几何、面积与材料接口

继续使用胶囊的长度、直径、位置和朝向作为单菌体状态，并增加可复用的体积、表面积和轴向尺寸派生接口。面积先作为几何结果，不立即变成限制；膜材料、受体拷贝数和表面展示资源以后以带单位的单菌体物质状态接入。

验收时需要看到：

- 生长和分裂能声明几何状态的更新、继承、分配和重置规则；
- 薄层容纳检查使用当前姿态和尺寸；尺寸未知时显示未知，不能假设通过；
- 等体积分裂与面积变化可以被记录，但不会偷偷增加或扣除膜材料；
- 材料预算接口关闭时不增加计算分支，开启后才由对应模块更新。

### 5. 边界、障碍物与拥挤

在几何接口稳定后加入胶囊与边界、障碍物、其他菌体之间的接触检查。运动、生长和分裂都使用同一套空间约束；“空间不足”作为可处理的受阻结果，“几何非法”作为失败结果，两者都不能静默生成更小的菌体。

验收时需要看到：

- 穿过边界、障碍或其他胶囊的帧不会作为正常结果发布；
- 生长或分裂受阻时保留前一状态，并给出可定位的原因；
- 一个时间步内任一菌体失败时，相关状态和物质账按规定整体回滚；
- 先支持确定性的碰撞检查，再扩展动量反弹、拥挤响应和障碍物模块。

### 6. 摄取通量、感知和环境变化的时序

把 `uptake_flux` 明确为逐菌体可观察通量，并规定它与移动、浓度采样、MCP 感知、PTS 调节和环境输入的先后关系。PCR 只作为“按时间执行环境变化”的类比；实际输入仍由通用事件或日程模块表达，温度不加入当前范围。

验收时需要看到：

- 每个通量都有时间区间、单位、来源模块和对应的环境损失；
- MCP/PTS 在连续耦合时使用同一段的定义浓度和通量，不因前端显示频率改变结果；
- `same_step`、`previous_step` 和必要的子步规则可被图编译器检查；
- 外部投料、耗氧和局部入口作为可替换事件或环境模块接入，并能回放。

### 7. 前端对象注册与专业工作区迁移

前端继续从后端 capabilities 和对象目录生成可放置对象。菌群以体积块为单位设置数量，再按固定种子散布到空间；障碍物、信号源、纤维等在协议声明前保持禁用提示。3D 视图要读取真实位置、朝向、尺寸和事件，重叠菌体必须保持可见且可选。

后续迁移包括变换工具、网格吸附、测距、检查与日志面板、后端声明的模块参数编辑，以及移动端的触控和面板滚动检查。英文继续作为默认语言，设置中切换语言。

验收时需要看到：

- 新模块登记后可以在不改核心界面的情况下出现在对象库和 Workflow；
- 批量放置、复制、删除和撤销都对应同一份工作区数据；
- 3D 与结果帧使用同一套 ID 和几何数据；
- 桌面、平板、手机横竖屏的浏览器模拟与实体设备实测分开记录。

### 8. 科学模块迁入、标定与加速

上述接口稳定后，逐项迁入营养耦合生长、耗氧、反应、趋化和经标定的分裂机制。每个模块都要有参数来源、适用范围、守恒检查和对照结果。性能基准按实际启用的模块、格点分辨率、时间步、菌体数量和输出频率记录；并行、稀疏场或 GPU 只在结果一致性通过后评估。

## 开工顺序

下一次实际开发从 N1 的类型/注册目录最小流程开始，同时明确任务状态机、幂等、错误和旧同步接口兼容合同；随后 N2 实现任务服务，N3 提前迁入首个真实趋化科学包。设计目标、候选比较、原生导出和 Wiki 交付进入 N4–N5。完整物性/接触/营养/材料归 N6，checkpoint 与环境迁移归 N7，标定和加速归 N8。模型必需的 N6 子任务可提前实施；原清单没有删除。具体依赖与验收见[开发路线](design/roadmap-and-acceptance.md)。
