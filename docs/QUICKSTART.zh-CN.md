# 第一次使用 Friskoli-CAD

Friskoli-CAD 在本机计算菌群运动、营养物质变化和材料转化。Space 编辑初始场景，Workflow 连接机制，Results 读取运行记录，Design 比较参数方案。模型采用研究性参数，尚未经过湿实验标定。

## 启动并完成一次运行

安装 Python 3.11 或更新版本。在项目目录创建环境并安装：

```powershell
python -m venv .venv
.\.venv\Scripts\python -m pip install .
.\start.ps1
```

浏览器打开 `http://127.0.0.1:8765`。如果 PowerShell 禁止运行脚本，可用 `.\.venv\Scripts\python -m friskoli_cad.replay_service --port 8765` 启动。Linux 和 macOS 的命令见 [User guide](USER_GUIDE.md)。

在欢迎页选择 **Modular foundation**。它有 8 个初始细胞和较小的网格，适合第一次运行。打开 **Workflow** 查看营养物质、摄取、代谢和运动节点，保持短时程设置，点击 **Run**。运行完成后，在 **Results → Data** 查看指标，再移动时间轴观察已保存的帧。Settings 可以切换英文和简体中文。

时间步长与步数决定模拟时长：`dt × steps`。保存帧间隔只影响输出频率，播放速度只影响查看过程。细胞数量、网格精度和模拟时长会影响实际计算时间。

## 完成第一次 Design 比较

第一次先比较游动速度，熟悉候选、对照和独立重复。加载 **Modular foundation** 后打开 **Design**，使用“短时速度比较示例”。它会设置两种速度、两个 seed，以及 12 步的短时运行；页面会说明设置的变化。

也可以手动填写：

| 字段 | 输入 |
| --- | --- |
| 目标指标 | `mean_displacement_um`，沿观测轴的平均位移 |
| 优化方向 / 菌群 | 最大化 / `cells` |
| 节点与参数 | `motility · speed_um_s` |
| 枚举值 | `5, 10`，单位 µm/s |
| seed | `0, 1` |
| 最少独立重复 | `2` |
| 每个 seed 相对对照的最小改善 | `0` |
| 运行预算上限 | `6` |
| 时间步长 / 步数 / 保存帧间隔 | `0.01 s` / `12` / `3` |

点击 **Generate candidates / 生成候选**。程序检查参数、连接和资源，生成两个候选与一个固定运动偏置对照，此时还没有运行模拟。这个通用对照保留基线的速度等参数，将运动偏置固定为 `0.5`；中心 PTS 预设附带的配对无反馈对照采用各自的定义，详见 [模型参考](MODEL_REFERENCE.md)。

选择全部候选及对照、全部 seed。每批最多 8 次运行，默认一批 4 次，因此总共 6 次时需要继续下一批。已完成的重复会被跳过；失败记录仍保留，重试会增加新的尝试记录。

完成后点击 **比较已完成运行** 查看各次结果，点击 **评价结果** 查看配对比较。每次独立运行是一份重复，单次运行中的 8 个细胞不能当作 8 次独立实验。

`mean_displacement_um` 有正负号，表示沿观测轴的位置变化。在这个短时示例中，初始方向随 seed 改变，提高速度可能让正向位移更大，也可能让负向位移更大。当前示例的两个 seed 没有同时满足改善条件，因此评价会显示“未给出推荐”。表格仍保留均值、标准差和每次配对改善，供进一步判断。推荐规则没有通过时，程序应直接说明原因。

## 保存、复查和分享

在 Design 导出 `.friskoli`，保存冻结的设计输入、候选、运行和来源信息。重新打开该文件可以查看已有记录。CSV 适合进一步分析，HTML 适合阅读报告；保留原生包便于复查完整输入。

同一个示例也可从命令行完整运行：

```powershell
.\.venv\Scripts\python examples/design/compare_speeds.py --out runs/first-design
```

脚本会实际运行 6 个任务，生成 `study.friskoli`、`report.html`、`report.csv` 和 `evaluation.json`。在应用中打开 `study.friskoli` 可检查冻结的设计与结果。生成的运行数据保存在被 Git 忽略的 `runs/` 中。

## 常见情况

候选被排除时，先读具体参数或路径的诊断。空白、未知或越界的参数值需要修正后重新生成。候选生成通过后，实际任务仍可能受到内存、时间或输出限制；先用小网格和短时程检查配置。

平均位移较大并不能直接说明菌群更接近材料。研究材料接触与转化时，分别查看接触、到达、停留和累计转化指标，并设置对应的观测区域。没有足够观测时间的漂移率会保留为空值。

修改后端代码或模块声明后，重启服务再运行。继续旧 checkpoint 需要兼容的源码与随机数环境；保留原来的软件环境可以减少复现实验时的版本差异。

需要增加机制时，从 [模块注册教程](EXTENDING.md) 和可运行的 `constant_bias` 示例开始。应用会检查模块声明和连接，模块作者仍需给出方程、适用条件与验证依据。
