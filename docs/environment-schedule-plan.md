# 环境变化日程 · 待开发

目标是让一场运行按预先保存的时间程序改变环境条件。例如先保持基质浓度，再输入一段诱导物，最后撤去；将来有温度模块后也可表示保温、升温和周期变化。每个控制量都需声明物理量、单位、物种或作用范围，不能凭一个通用数字直接改写任意环境状态。

第一版计划在**同一环境实现内**施加变化。运行中更换环境模块需要另外定义其内部状态如何迁移；当前没有这套规则，不纳入第一版。基础版日程难度为中等，状态迁移难度更高。

## 实现前需要确定

1. **时间边界。** 定义某时刻的控制变化在时间步的哪个边界生效；第一版让变化时刻与计算步边界对齐。非对齐时刻须明确拆分时间步或拒绝，不能悄悄推迟到下一帧。计算步与输出帧间隔保持独立。
2. **输入与状态。** 环境模块声明可接受的控制输入及单位；日程作为版本化运行设置保存，包含时间、值、来源和所用模块版本。不能把浓度场的直接赋值混同于实际投料机制。
3. **外部物质账。** 对注入、移除或理想维持浓度，记录每种物质每步的外部增减量。用“初始场物质量 + 外部净输入 − 菌体摄取 = 当前场物质量”检查守恒；温度变化另用适合其机制的记录，不套用分子数账。
4. **复现检查。** 覆盖薄层和 3D、相邻变化、周期重复、无变化日程、变化恰好落在步边界，以及错误单位或物种。输出帧需能追溯实际施加的控制和时间。

开发顺序：先完成空间尺度与时间步的诊断，再建立日程格式和最小的浓度/外部供给例子，之后接入运行服务与界面。更复杂的温度、pH、流速程序在各自环境模块具备明确物理含义后加入。
