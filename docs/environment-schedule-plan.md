# 环境变化日程 · 待开发

目标是让一场运行按预先保存的时间程序改变**化学物种**的外部输入。例如先供给基质，再短时加入诱导物，最后撤去；需要时可重复一组时间段。PCR 的时间程序仅作为日程形式的类比，本项目当前没有温度计算任务。每个控制量都需声明物种、单位和作用范围，不能凭一个通用数字直接改写任意环境状态。

氧可登记为另一种物质，拥有自己的浓度场、初始与边界条件。菌体耗氧、氧的输运与气液交换由相应模块承担；仅登记 `oxygen` 这个名称不会自动得到这些机制。当前协议已能用 `species` 参数区分连接的物质，但还没有项目级物种目录或耗氧模块。

介质黏度属于环境属性，可由模块参数或环境状态场表示；它不作为化学物种浓度登记。以后若要按日程改变黏度，需要另行声明控制对象、单位和生效机制。本计划的第一版仍只处理已声明物种的外部输入。归属原则见[状态归属说明](state-ownership.md)。

第一版计划在**同一环境实现内**施加变化。运行中更换环境模块需要另外定义其内部状态如何迁移；当前没有这套规则，不纳入第一版。基础版日程难度为中等，状态迁移难度更高。

## 实现前需要确定

1. **时间边界。** 定义某时刻的控制变化在时间步的哪个边界生效；第一版让变化时刻与计算步边界对齐。非对齐时刻须明确拆分时间步或拒绝，不能悄悄推迟到下一帧。计算步与输出帧间隔保持独立。
2. **物种、输入与状态。** 为每种物质保存标识、单位和初始条件；环境模块声明可接受的控制输入。日程作为版本化运行设置保存，包含时间、物种、值、来源和所用模块版本。不能把浓度场的直接赋值混同于实际投料机制。
3. **外部物质账。** 对注入、移除或理想维持浓度，分别记录每种物质每步的外部增减量。验证“初始场物质量 + 外部净输入 + 模块净生成 − 模块净消耗 = 当前场物质量”。
4. **复现检查。** 覆盖薄层和 3D、相邻变化、周期重复、无变化日程、变化恰好落在步边界，以及错误单位或物种。输出帧需能追溯实际施加的控制和时间。

开发顺序见[总安排](development-order.md)：先做固定菌体的基础扩散与移动的数值检查，再建立项目级物种目录、日程格式和最小的化学物质外部供给例子，之后接入运行服务与界面。耗氧和气液交换按各自模块及其科学依据逐项实现。
