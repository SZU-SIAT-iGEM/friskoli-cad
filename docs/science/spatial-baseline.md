# 空间基线：底物、养分场、接触降解与运动

本阶段使用 `spatial-unbiased-v1`。它把实体底物、可溶养分及来源机制分开登记，并把它们接入同一数值事务。参数仍为构造验证值；没有把轨迹动画视作趋化有效性的证据。

## 物质与来源的区别

PTS 示例只使用一个可溶物种 `nutrient`。实体底物降解后释放它，直接放置的引诱物源也释放它；两种来源共同补给唯一的浓度场。PTS 请求、接受摄取和信号都引用这个物种。多个来源不会创建多份互不扣减的养分库存。

| 注册内容 | ID | 数值职责 |
| --- | --- | --- |
| 固定障碍物对象 | `space.obstacle_box` | 引用 `space.axis_aligned_obstacle@1.0.0`；胶囊不可穿越，扩散面无通量 |
| 可降解底物对象/模块 | `material.degradable_box` | 盒体几何、产物物种、有限的可释放养分当量 |
| 引诱物源对象 | `source.attractant` | 引用 `source.finite_local@1.0.0`；按显式速率自行释放，有有限总量 |
| 全局接触降解 | `reaction.contact_degradation` | 读取所有材料与表面酶能力，按接触、酶预算、速率和剩余量生成释放提案 |
| 表面酶能力 | `surface.enzyme_activity` | 声明各菌群每菌可用于降解的酶量；没有能力的菌体不降解 |
| 局部扩散场 | `field.diffusive_local` | 按物种汇集已注册来源，扩散并按统一库存接受摄取 |

`initial_molecules` 在实体底物上表示**可释放的可溶养分当量**。它不表示聚合物链条数，也没有根据这一个数推算密度、质量或盒体体积。具体聚合物、产物、化学计量和表面酶动力学需后续独立模块与证据。有限自释放源目前采用分段线性耗尽律，不等同于已验证的化学降解反应。

注册对象只有一份几何真值：图节点参数。前端放置、参数编辑、初始化、碰撞及场掩码都引用这些参数。未知对象 adapter 或无实际实现的模块保持不可运行。

## 自动生成与删除约束

放置底物时，依据 Catalog 的 `initializer.requirements` 生成全局降解模块，并复用同物种的唯一扩散场。全局模块提供 `material.degradation` 角色。只要仍有底物依赖这一角色，就不能删除最后一个兼容机制；必须先引入支持该角色和执行规则的替代机制，或移除依赖它的底物。

声明同名角色仅是必要条件。新的科学实现仍需在后端注册、通过参数及执行校验，前端不能用一段标签授予求解能力。本版提供一个接触降解实现，不宣称已经交付任意插件安装。

## 一个时间步

1. 固定步初的姿态、场、材料库存、信号、酶能力与 RNG 状态。从步初场生成 PTS 请求。
2. 用胶囊表面到材料盒体的实际间隙识别接触范围。每菌总酶能力在接触的未耗尽材料间分配，避免同一份酶在多个底物上重复满额使用。
3. 降解请求受 `kcat_s × enzyme_copies × dt` 和材料剩余量约束；同一材料的所有菌体共同分配库存。产物释放到接触菌所在的流体体素，进入可共享的场。
4. 叠加直接来源的有限释放，按 CFL 条件自动划分扩散子步，再进行局部共享摄取。只有接受量扣场、增加胞内累计并驱动 PTS 信号。
5. 生成各菌体的无偏 run/tumble 事件；合并事件时间后同步检查平移与转向的碰撞。通过全部数值与帧校验后，一次提交场、库存、位姿、信号、事件时钟及 RNG。

降解产物不会直接赠给执行降解的菌体。特别是步初局部浓度为零时，该菌的本步 PTS 请求为零，即使本步释放了养分，也要在后续步骤从场中摄取。源释放与 PTS 转运各有速率上限；这是防止一次性全量转移的机制，不额外编造“每次最多吃固定百分比”的生物规则。大时间步的误差仍须做收敛检查。

接触范围 `contact_range_um` 是显式的近表面反应距离，示例值没有实验标定。远处路径被碰撞保护拒绝，并不自动构成当前接触。当前算法按步初位置判断反应，不声称已经解析了一步内部的全部接触驻留时间。

部分降解时，底物盒体边界暂时保持不变，库存减少；完全耗尽那步仍按步初几何计算，提交后退出碰撞与场阻挡，之后养分可扩散进原占据体积。这是明确的几何近似，尚无连续侵蚀、断裂、孔隙率或产物抑制模型。

## 碰撞、随机性与可恢复状态

胶囊碰撞覆盖胞体—胞体、器壁和注册实体盒，包含整段运动的检查。无法证明安全的提案保守地保持区间起始姿态，返回 blocked；不会把阻挡伪造成死亡。拥挤时可能低估运动，未包含接触力、摩擦和流体动力学。见[碰撞参考](collision-baseline.md)。

事件时钟与随机流按运行 seed、模块、菌群、稳定菌体 ID 和用途隔离，步失败时连同场和科学状态一起回滚。输出帧频率不改变数值步。分步方式仍可能影响场算子拆分及碰撞阻挡，不能把随机序列可复现等同于任意步长轨迹相同。见[随机机制](random-walk-baseline.md)与[场算法](local-fields-baseline.md)。

Python 运行器有版本锁定的 JSON checkpoint，保存完整 RNG 与可恢复状态；任务服务仍未开放 pause/resume。前端保存的设计文件是初始条件，任务 frozen input 是本次运行的输入，两者均不能冒充运行中间态。

2026-10-01 的 M4 增量提供[自包含文件及命令行恢复](../checkpoint-files.md)，并补齐帧检查器、最后一步碰撞诊断与库存账本一致性检查。连续/保存恢复、失败重试和输出帧频率的实际验收见 [M4 记录](../archive/verification/verification-m4.md)。当前固定种群不含外部日程或出生/死亡事件；这些能力后续接入时必须扩展完整状态映射。

## PTS 与 MCP 的后续对照

PTS 案例关注有限养分的来源、实际摄取与信号。摄取率和信号相关有实验研究依据，但本项目当前采用的现象学 EI/CheA/CheY 方程及构造参数不因此成为已标定模型。[Somavanshi 等，2016，Sugar Influx Sensing by the Phosphotransferase System of Escherichia coli](https://journals.plos.org/plosbiology/article?id=10.1371/journal.pbio.2000074)。

MCP 对照计划采用均匀、持续补给的营养背景和独立引诱物梯度，隔离受体感知/适应的作用。这是该案例的环境条件，不能作为所有 MCP 的定义。经典实验已展示不可充分代谢的氨基酸类似物也可充当引诱物。[Mesibov 与 Adler，1972，Chemotaxis toward amino acids in Escherichia coli](https://pubmed.ncbi.nlm.nih.gov/4562400/)。

因此物种的“营养物”“受体配体”“PTS 摄入物”应由具体模块与实验设计声明，允许重合，也允许分离。当前空间示例的运动保持无偏；MCP 感知/适应和 PTS 信号驱动运动属于下一阶段，不能从这个示例报告趋化增益。
