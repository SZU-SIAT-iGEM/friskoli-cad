# 环境变化日程：已实现部分与后续安排

2026-10-03：`modular-spatial-v1` 已通过普通模块实现局部 pulse/rate、完整初始数组、受控浓度交换、显式耗氧及气液交换。t=0 初始化与 (t,t+dt] 日程边界分别处理，checkpoint 保存已消费事件状态；旧 profile 保留原规则。当前实现与来源见[模块扩展](science/modular-processes.md)，下文保留原设计动机。

2026-10-01 实施更新：N3/N6 必要子集已包含空间有限自释放源和接触降解产物源；M4 已提供[空间 checkpoint 文件与独立进程恢复](checkpoint-files.md)。任务暂停续算及运行中环境迁移仍安排在 N7；见[新版路线](design/roadmap-and-acceptance.md)。环境热切换不先于首个趋化设计案例，原有日程与重划能力继续保留。

legacy 执行规则已在[项目物种目录与输入日程](project-schedule.md)中实现：项目快照保存物种初始浓度、全域外部输入速率、时间变化点、来源和可选重复周期。运行器只在时间步边界施加变化，并逐物种记录外部净输入。使用同一项目快照可以重复运行。新空间 profile 当前拒绝非空外部 controls，没有日程游标可恢复。PCR 的时间程序仍只作为日程形式的类比；温度目前不在开发计划中。

`oxygen` 可以只登记而不进入运行计算；需要时才接入自己的浓度场和日程。登记名称不自动产生恒定浓度、耗氧、输运或气液交换机制；这些机制需要独立模块与科学依据。介质黏度属于环境属性，不登记成化学物种。其状态归属见[状态归属说明](state-ownership.md)。

有限局部源已能在空间中按登记位置持续释放并耗尽；科学 profile 已支持初始线性梯度与显式均匀营养储库；时变局部入口、瞬时投料、任意初始场及更复杂的浓度维持规则仍需分别实施。运行中更换环境模块还要定义旧状态怎样映射到新模块，不能由输入日程自动代替。PTS/MCP 信号与运动已接入[科学 profile](protocol/chemotaxis-profile.md)，顺序见[开发安排](development-order.md)，逐项缺口见[剩余工作清单](remaining-work.md)；旧项目仍保留[原移动时序](moving-cells.md)。
