# 逐帧胶囊尺寸与演示性生长 · 阶段 3m

项目 `0.2.0` 的初始尺寸现在可以进入逐菌体结果帧。新帧增加 `frame_version: 0.2.0`，每个菌体的 `geometry` 为胶囊总长与直径，尺寸未知时为 `null`。旧项目仍产生原来的 `0.1.0` 帧，不增加字段；一段帧序列不能中途更换格式。行为图、模块声明和运行元数据继续使用 `protocol_version: 0.1.0`。项目格式版本、连接协议版本和结果帧版本各有明确用途。

```json
{
  "protocol_version": "0.1.0",
  "frame_version": "0.2.0",
  "cells": [
    {"id": "cell_0", "geometry": {"shape": "capsule", "length_um": 2.1, "diameter_um": 0.8}}
  ]
}
```

上面只摘出相关字段；[完整运行示例](../examples/runtime/linear_growth.project.json)包含场地、菌体、物种目录、行为图和运行元数据。运行器在每步提交后按稳定的菌体 ID 写入新尺寸。外部帧校验会检查格式、胶囊长宽关系及帧版本连续性。

`growth.linear_elongation@1.0.0` 是一个可替换的**演示性数值模块**。它要求每个菌体已有胶囊尺寸，使用菌体组参数 `elongation_rate: um/s`，按 `L(t+Δt) = L(t) + elongation_rate × Δt` 增加胶囊总长，直径保持不变。模块输出逐菌体的 `length` 与 `diameter`，运行器把这一对输出认作该组几何状态的唯一来源；同组两个几何来源会报错。未接入这个模块的旧行为图不会执行生长计算。

薄层会在更新后重新检查胶囊的 Z 向占据高度。若这一步长出的菌体放不进薄层，时间、几何与其他状态都保留在上一步。这个增长率没有由营养、摄取通量、细胞质量或分裂周期计算，也没有物质守恒含义。运动仍按中心点反射，当前胶囊尺寸不参与墙面或菌体间接触。

在仓库根目录运行：

```powershell
$env:PYTHONPATH='src'
python examples/runtime/run_growth.py
```

示例只有一个菌体，起始总长 `2.0 µm`、直径 `0.8 µm`，以演示值 `0.2 µm/s` 伸长；每 `0.5 s` 输出一帧。项目登记了氧，但图中没有氧计算节点，因此运行快照没有氧浓度场。[测试](../tests/test_growth.py)同时检查旧帧兼容、多个菌体各自的几何、移动与摄取结果不受这个演示模块改变、过度生长时整步回滚，以及错误帧被拒绝。

生长模块本身不会自动分裂；将它连接到[长度 adder 分裂模块](adder-division.md)后，运行器可按新增长度触发分裂并分配逐菌体状态。
