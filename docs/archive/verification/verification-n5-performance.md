# N5 完整场景性能诊断与聚集目标

2026-10-03，执行内核基线 `6a14e14`。本次完成性能分析与计划修订，**尚未实现新的加速**。没有改动科学参数、时间步、执行内核、主服务或用户保存的任务。机器可读数据见[测量摘要](science/verification/n5-performance-baseline.json)，复现工具见[profile_spatial.py](../examples/runtime/profile_spatial.py)。

## 实际目标与当前结果

用户的目标是在可用的壁钟时间内看到真实趋化聚集。完整10000步、12小时合同与每秒步数仍需记录，但不能代替这一结果。后续同时记录计算进度、已显示帧的模拟时间、壁钟时间，以及PTS与对照的径向分布；判断聚集时同时比较初始分布，区分启动暂态、器壁滞留、增长和趋化响应。

用户暂停的任务 `run_fcb0b86ffc534ae99d78b9a565231920` 从启动到暂停耗时 **1550.328 s，约25分50秒**，完成 **745步 / 7.45 s**，平均 **2.081 s/步**。每100步保存一次，即1 s模拟时间；前七个100步窗口各耗约179–231 s。当前配置因此约3–4分钟才产生一张新的保存帧。

若保持该历史平均速度，10000步约需5.78小时；这是线性外推，未包含未来菌群变化、热状态和资源竞争，不能当作完成时间承诺。用户任务和第745步checkpoint保持原样。

## 测量范围

- 相同冻结输入：128 µm立方域，256³网格，0.5 µm格距，100 PTS + 100 control，seed 42，dt=.01 s，D=65 µm²/s，float64，`chemotaxis-spatial-v1`及CUDA。
- 本机：Windows 10 build22621、Python3.11.9、NumPy2.1.2、CuPy13.6.0、RTX4060 Laptop（驱动报告8188 MiB显存）。未独占整台机器，不把共享主机下短样本差异解释为优化收益。
- 分别从原始项目和第745步checkpoint在独立进程中计算少量真实步骤。初始化、普通计时、阶段计时、cProfile和文件输出分开；执行源码hash与原任务逐份一致。
- 初始第2–4步普通计时1.268–1.604 s/步；第745步恢复后的普通计时两轮分别为1.467–1.625及1.776–1.921 s/步。cProfile额外增加Python调用开销，下面的占比使用另一轮低侵入阶段计时，不使用cProfile的占比冒充真实耗时。

## 一个完整数值步花在哪里

第752–756步共测 **8.688267 s**，平均 **1.737653 s/步**。下表互不重复，扣除了被单独计时的子阶段；这些是壁钟耗时，不是CPU指令耗时或硬件内存带宽。

| 工作 | 秒/步 | 占比 | 实现中的原因 |
| --- | ---: | ---: | --- |
| 全场库存统计 | 0.530 | 30.5% | 每步4次 `_mass`；每次创建128 MiB转换数组并检查、分块求和 |
| 运动与碰撞 | 0.294 | 16.9% | 随机事件边界多次推进整组胶囊，重复几何检查 |
| CUDA扩散及传输 | 0.276 | 15.9% | 18个稳定子步、上传/下载及返回值校验 |
| 场状态、输出与冻结校验 | 0.228 | 13.1% | 4次场state校验，加outputs/state重复扫描 |
| 逐帧结构与连续性校验 | 0.134 | 7.7% | 所有数值步都执行通用JSON Schema遍历与跨帧检查 |
| 可写候选及不可变场存储 | 0.094 | 5.4% | 保留原状态以保证失败不提交，随后生成不可变场 |
| 场事务其余部分 | 0.073 | 4.2% | 释放、共享摄取、转移精度审计等 |
| 生理与生命周期 | 0.065 | 3.7% | 生长、表达、健康及生命周期处理 |
| 其他 | 0.044 | 2.5% | 准备、细胞帧构建、观测和提交等 |

单场128 MiB、mask16 MiB。4次库存统计每次仍遍历1677万个格点，即使该次释放/摄取只改变很少的格点。源码估算全部CPU数组操作的逻辑流量约6 GiB/步量级，**不是硬件测得的DRAM流量**。

CUDA子步实际为 `ceil(dt / (0.9 × dx²/(6D))) = 18`，每外部步约3.02亿voxel updates。GPU内部子步之间没有host往返；每次完整扩散调用上传一个场和mask，末尾下载一个场，约272 MiB/物种/步。

另对第745步同一场做了三次独立CUDA阶段实验，结果逐值等于原 `diffuse_cuda`：GPU event测得18个kernel共0.076–0.116 s，上传与缓冲准备0.022–0.071 s，下载0.050–0.065 s，结果校验0.031–0.038 s。该实验在阶段间同步，只解释扩散调用内部成本，不能作为完整任务提速结果。数据见机器摘要。

### 输出与已有优化

一次8×8×8合并预览数组生成约0.042 s；这不含worker输出校验、序列化、IPC、原子写入及前端绘制。一次独立checkpoint保存约4.429 s、约420 MB。它包含同一浓度场在local_fields、outputs、state中的三份数组，有明确去重空间；checkpoint并非每个数值步都保存，因此这不能解释主要持续耗时。

已有机制不能被重复计为新优化：梯度只采样每菌体附近6个邻居；静态障碍mask已有缓存；快照共享不可变场；`_freeze`不再复制已有bytes owner；JSON Schema和validator也已缓存。真正的热开销是反复扫描/通用遍历、几何计算、扩散和传输。

已保存的最后一帧是第700步/7 s，不能把745步checkpoint时间写成这一帧的时间。两组各100个初始菌体，初始平均中心距离均58.9769 µm，r≤10/20/40 µm人数均为1/1/15。

| 7 s指标 | PTS | control |

| 平均中心距离 | 62.904 µm | 69.918 µm |
| 相对初始的平均向内位移 | −3.927 µm | −10.941 µm |
| r≤10 / 20 / 40 µm人数 | 0 / 3 / 15 | 1 / 2 / 5 |
| r≤40 µm初始菌体平均停留时间 | 1.0605 s | 0.5870 s |
| 距任意器壁不足1 µm人数 | 33 | 60 |
| 保存步的blocked人数 | 24 | 47 |

目前只能说PTS比对照少向外扩散，不能称为明确中心聚集。第1 s PTS实际运动bias均值0.99706，对照固定0.135713；tumble人数48/11。第7 s PTS均值仍为0.34645。来源B的零CheY/零memory初态会产生启动暂态，固定bias对照不跟随该暂态，早期径向差包含总体运动行为差异。

已核对实际输入及源码的链路：accepted_amount/dt → accepted_flux → EI → CheA → CheY → memory → 下一步motor hazard，未发现明显反号、分子/秒单位错误或漏接。该检查不证明最终一定聚集。参数与原有初态说明见[来源B场景](science/n5-b-lifecycle.md)；过去小场B的群体效应尚未分辨，不能用其结果替代本场景，见[N3研究限制](science/n3-comparison.md)。

后续验收同时呈现：两组各自的向内位移、20/40 µm内人数和比例、停留时间、死亡/分裂人数，以及相应模拟时间和壁钟时间。要求连续多个保存时点出现可辨认趋势，不能从单帧中挑一个半径宣称成功。10 µm内单个菌体就能带来约5倍体积富集，必须显示实际人数。独立seed、无源及初始化对照用于进一步区分趋化、启动和边界影响，不能通过调参制造正结果。

## 下一步实施顺序

1. **P02：系统层消除重复工作。** 对不可变场版本复用已完成的校验；metadata-only变更不重新扫描浓度；用保持原1024元素分块与求和顺序的块级库存统计，让局部释放/摄取只更新受影响块。不能直接换成不同求和顺序或关闭守恒检查。
2. **P02：碰撞与内部帧规则。** 复用几何数据、向量化常见安全情况；给固定结构的内部帧建立等价快速检查，保留完整跨帧/事件/ID/几何校验。外部输入继续严格验证，异常诊断不丢失；以现有schema和参考碰撞实现作差分检查。
3. **P03：扩散和设备执行。** 先测device mask与workspace复用、传输减少；继续评估能减少内部扩散步的求解机制。改变数值算法必须显式声明适用边界、稳定性、非负性、守恒和收敛依据，不能隐藏在案例判断中。仅优化CPU仍受现有扩散耗时限制，不能预先承诺分钟级结果。
4. **P04：任务与显示。** 去重checkpoint中可安全共享的数组，保留shape、hash和原子发布；区别真实计算推进与保存帧延迟，改善有界实时预览。优化后的源码与旧checkpoint锁不同，保留旧环境或提供经验证的显式迁移，不替换锁冒充兼容。
5. **P05：以可见聚集检验效果。** 使用上述同场景指标衡量“达到可辨认聚集时的壁钟时间”；完整10000步与长期科学验收继续保留。若仍无聚集，继续诊断科学机制及场景边界，不能用加速后的动画代替。

`.1 s`默认外步仍待独立时间尺度核对；反应时标不能直接证明数值步长收敛。即便改为`.1 s`，本显式扩散也需174个内部子步，不能把主步减少十倍宣称整体快十倍。原任务和保存预设本次未改动。

## 复现

使用冻结Task输入JSON，输出目录放在仓库外；指定checkpoint时工具要求项目、seed和backend与输入一致。从项目初态测量时去掉 `--checkpoint`。

```powershell
$env:PYTHONPATH='src'
.venv/Scripts/python.exe examples/runtime/profile_spatial.py --task-input <input.json> --checkpoint <checkpoint.zip> --out <new-output-directory> --steps 5 --stages --publication
```

工具单独初始化后，先执行1个warmup步，再执行5个普通计时步、5个阶段计时步和5个cProfile步；它们覆盖连续的不同状态。`--publication`再测一次预览数组生成和新的checkpoint保存。输出包含来源hash、参数、环境、普通计时、阶段计时、cProfile、场和帧指纹。场/帧指纹不等于完整RNG、账本与checkpoint等价证明。

本次实际大数组、profile原文件与临时checkpoint均在仓库外的 `friskoli-n5-perf-20261003` 临时审计目录；可读测量摘要随文档提交。没有运行完整万步、12小时任务、前端设备验收或安装包构建；没有宣称获得加速收益。
